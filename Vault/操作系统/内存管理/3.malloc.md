
## malloc分配内存(brk和mmap的区别)
#### brk()
- malloc分配内存较==小==时通常从堆区分配，必要时通过brk/sbrk扩展堆
- brk()系统调用通过移动==堆顶指针==向高地址扩展堆空间
- free释放后通常先放回分配器的空闲块，可能被后续malloc复用；满足条件时也可能归还操作系统
- 只用brk：频繁申请和释放可能产生大量==外部碎片==，虽然总空闲内存足够，但缺少连续空间
#### mmap()
- malloc分配内存较==大==时通常通过mmap申请内存
- mmap()在==内存映射区域==建立映射，可以是文件映射，也可以是匿名映射
- 大块内存通过mmap分配后，free时通常会解除映射并归还操作系统
- 只用mmap：系统调用开销较大，小内存频繁分配会降低程序性能

## malloc和new的区别
- malloc是c语言的库函数，new是c++的内置运算符
- malloc需要以字节为单位指定内存大小；new根据类型自动计算单个对象大小，数组new[]需要指定元素数量
- malloc只申请原始内存，不调用构造函数；new会分配内存并调用构造函数，也可以进行初始化
- 释放方式：malloc-free，new-delete（数组 new[]-delete[]）
- 成功处理：malloc返回void* 类型指针（需要强制转换），new返回对应类型的指针
- 失败处理：malloc返回nullptr，new默认抛出std::bad_alloc；使用new(std::nothrow)时失败返回nullptr

## free后的风险
**1. 指针悬空问题：**
```cpp
#include <cstdlib>

int main() {
    int* p = static_cast<int*>(std::malloc(sizeof(int)));
    if (p == nullptr) {
        return 1;  // 申请失败
    }

    *p = 10;
    std::free(p);
    p = nullptr;
}
```
此时释放后的指针已置为 `nullptr`，可以避免继续使用悬空指针。
**2. 重复释放问题：** 同一块堆内存free两次
**3. 内存泄漏问题：**  程序申请了堆内存，但没有释放这块内存，导致一直占用进程内存
