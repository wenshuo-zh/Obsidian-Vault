## 编译阶段

`test.c` ->
**预处理** -> `test.i(预处理文件)` -> 
**编译** -> `test.s(汇编文件)` ->
**汇编** ->`test.o(机器码文件)` ->
**链接** -> 
可执行文件

如果跳步骤就会把连带把之前的步骤执行了
- 预处理：头文件展开，宏替换，删除注释
- 编译：语法词法分析，得到汇编语言
- 汇编：翻译汇编指令成二进制机器码、生成符号表
- 链接：重定位，符号解析

## 静态库和动态库
### 静态库
- 编译阶段把一堆`.o`文件打包成一个单独的文件，这个文件就是静态库，一般命名`libxxx.a`
- 链接时，链接器只会从静态库中提取程序实际需要的目标模块，并合并到可执行文件里
- 程序运行时不依赖这个静态库文件
`ar rcs libxxx.a xx.o xxx.o`

### 动态库
- 动态链接器加载的库，本身是可重定位的共享目标文件，可被多个程序共用，通常命名为`libxxx.so`
- 链接时检查函数符号在动态库是否存在，符号合法性校验、符号引用（记录引用外部符号），重定位条目（在程序的哪个位置，填外部符号的地址）
- 程序运行时，动态链接器在进行真正的链接过程
`gcc -c xx.c -o xx.o -fPIC` 
	`-c`：只编译汇编，不链接，生成`.o`文件
	`-fPIC`: 生成与位置无关代码（这样动态库可以被加载到进程虚拟地址空间的任意位置，实现多进程共享同一份库代码。）
`gcc -shared -o libxxx.so xx.o xxx.o`
	`-shared`：输出产物是动态共享库，不是可执行程序。
`gcc main.c -o main2 -L ./ -lmath`
	`-L ./`：去当前目录找库文件
	`-lmath`：链接libmath.so

### 静态库和动态库的区别
- 文件大小：
	图中可以看到，静态库可执行文件占内存大，多个程序同时运行，内存里会有多个副本
	动态库占内存小很多，多个程序共用一份动态库
- 扩展性和兼容性：
	静态库代码修改后，必须从新编译可执行文件再链接才能生效
	动态库只需要更新动态库本身，所以使用动态库更方便升级和部署
- 依赖原库文件
	静态库执行不需要依赖原库文件，动态库需要
