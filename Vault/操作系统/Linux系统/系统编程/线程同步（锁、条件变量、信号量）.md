## 互斥锁
多线程竞争操作共享变量的这段代码叫做**临界区**。多个进程同时操作临界区会产生错误，所以这段代码应该**互斥**，当一个线程执行临界区时，应该阻止其他线程进入临界区。

**`pthread_mutex_init()`** 
	互斥锁初始化
	第一个参数传mtx，第二个参数默认传NULL
**`pthread_mutex_lock()`** 和 **`pthread_mutex_unlock()`** 
	给互斥量加锁和解锁，传mtx
**`pthread_mutex_destory()`** 
	销毁互斥锁，传mtx

五个线程，每个线程a++十万次，最后打印a为五十万
```c
int a = 0;
pthread_mutex_t mtx;

void *thread(void* arg){
    for(int i = 0; i < 100000; i++){
        pthread_mutex_lock(&mtx);   // 加锁：进入临界区
        a++;                       // 临界区：修改共享全局变量a
        pthread_mutex_unlock(&mtx); // 解锁：退出临界区
    }
    return NULL;
}

int main(int argc, char *argv[])
{
    pthread_mutex_init(&mtx, NULL); // 初始化互斥锁

    pthread_t tid[5];
    for(int i = 0; i < 5; i++){
        pthread_create(&tid[i], NULL, thread, NULL); // 创建5个子线程
    }
    for(int i = 0; i < 5; i++){
        pthread_join(tid[i], NULL); // 等待5个线程全部执行完毕
    }
    printf("a = %d\n", a);
    pthread_mutex_destroy(&mtx); // 销毁锁
    return 0;
}
```

**`pthread_mutex_trylock()`** 
	尝试给互斥量加锁，不会阻塞
	成功返回0、加锁不成功直接返回错误号（EBUSY）
上一个代码线程部分改成try锁，循环尝试拿锁
```c
void *thread(void* arg){
    for(int i = 0; i < 100000; i++){
        while(1){
            int ret = pthread_mutex_trylock(&mtx);
            if(ret != 0 && ret == EBUSY){
                printf("not get mutex lock\n");
                continue;
            }
        //ret == 0 成功拿到锁
        a++;
        pthread_mutex_unlock(&mtx); 
        break;
    }
}
```

## 读写锁
读优先：只要有读者正在持有读锁，新来的读请求直接放行；哪怕已经有写线程在排队等着，新来的读照样能抢到锁。
```c
pthread_rwlock_t rwlock;

void* thread1(void* arg){
    
    pthread_rwlock_rdlock(&rwlock);
    printf("1加锁成功\n");
    sleep(3);
    pthread_rwlock_unlock(&rwlock);
    printf("1解锁\n");
}
void* thread2(void* arg){
    
    pthread_rwlock_wrlock(&rwlock);
    printf("2加锁成功\n");
    sleep(3);
    pthread_rwlock_unlock(&rwlock);
    printf("2解锁\n");
}
void* thread3(void* arg){
    
    pthread_rwlock_rdlock(&rwlock);
    printf("3加锁成功\n");
    sleep(3);
    pthread_rwlock_unlock(&rwlock);
    printf("3解锁\n");
}
int main(int argc, char *argv[])
{
    pthread_rwlock_init(&rwlock, NULL);
    pthread_t tid1, tid2, tid3;
    pthread_create(&tid1, NULL, thread1, NULL);
    sleep(1);
    pthread_create(&tid2, NULL, thread2, NULL);
    sleep(1);
    pthread_create(&tid3, NULL, thread3, NULL);
    pthread_join(tid1, NULL);
    pthread_join(tid2, NULL);
    pthread_join(tid3, NULL);
    pthread_rwlock_destroy(&rwlock);

    return 0;
}
```
一三是读锁，二是写锁
![[Pasted image 20261001213629.png]]
一拿到读锁，二是写锁先堵塞，三是读锁又能拿到锁
一三解锁后二能加锁

适用：银行账户场景：**读多写少**（查询余额非常频繁，存钱修改很少）。
	- 如果只用普通互斥锁（pthread_mutex）：不管是查询还是存钱，全都串行排队，哪怕 10 个人同时查余额，也只能一个一个查，性能很差。
	- 读写锁：读和读可以并行；写和任何操作互斥。非常适合这种大量读、少量写的业务。
