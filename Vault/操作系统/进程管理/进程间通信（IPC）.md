# 管道、消息队列、共享内存

## 管道

- 存在于内核缓冲区，通常用于单向通信，数据先进先出（FIFO）
- 管道是==字节流==，没有消息边界；一次 `read()` 可能读到半条消息，也可能读到多条消息
- 管道缓冲区空且仍有写端时，再读会阻塞；管道缓冲区满时，再写会阻塞
- 写端全部关闭，缓冲区没有数据，再次读时 `read()` 返回 `0`，表示 EOF，读取正常结束
- 读端全部关闭后再次写：内核发送 `SIGPIPE` 信号，默认会终止写进程；若忽略或捕获该信号，`write()` 返回 `-1`，`errno` 为 `EPIPE`

### 匿名管道 pipe 和命名管道 FIFO 的区别

- 匿名管道没有名字标识，只存在于内存中；命名管道在文件系统中以类型为 `p` 的特殊文件作为入口
- 匿名管道通常用于有亲缘关系的进程通信，因为 `fork()` 后子进程会继承文件描述符；命名管道可以让无亲缘关系的进程通信
- 匿名管道通过 `pipefd[0]` 读、`pipefd[1]` 写；命名管道通过 `open()` 打开管道文件

```cpp
int rfd = open("./myfifo", O_RDONLY);  // 读端
int wfd = open("./myfifo", O_WRONLY);  // 写端
```

## 消息队列

- 存在于内核中，以==一条条消息==保存，消息有边界
- 每条消息可以带类型，接收进程可以按类型读取消息
- 不要求进程有亲缘关系
- 队列为空时，接收操作默认阻塞；队列已满时，发送操作默认阻塞；非阻塞模式下会立即返回错误
- 消息队列独立于创建进程，创建进程退出后通常仍存在，需要手动删除
- 消息队列没有像管道一样由“写端全部关闭”产生 EOF 的机制

## 共享内存

- 将不同进程的虚拟地址空间映射到==同一块物理内存==，进程可以直接读写共享数据
- 数据交换阶段不需要在进程和内核缓冲区之间反复拷贝，通常是最快的本地 IPC 方式
- 共享内存不负责同步，需要信号量、锁等方式保护临界区，防止数据竞争

### 临界区和信号量

- **临界区：** 多进程或多线程访问、修改共享资源的代码段
- **信号量：** 本质是计数器，用于同步、互斥或资源数量控制

生产者消费者模型：

```text
empty：空闲格子数量，初始值 = 缓冲区容量
full ：已填数据数量，初始值 = 0
mutex：保护共享缓冲区、读写下标等临界区
```

```text
生产者：wait(empty) → 写入数据 → post(full)
消费者：wait(full)  → 读取数据 → post(empty)
```

- 生产者写入一条数据后：`empty - 1`、`full + 1`；`empty` 为 `0` 时阻塞
- 消费者读取一条数据后：`full - 1`、`empty + 1`；`full` 为 `0` 时阻塞
- 多生产者、多消费者时，还需要 `mutex` 防止多个进程同时修改共享缓冲区的下标和数据

## 对比

| 通信方式 | 数据位置    | 核心特点           | 是否需要额外同步   |
| ---- | ------- | -------------- | ---------- |
| 管道   | 内核缓冲区   | 字节流、FIFO、无消息边界 | 管道提供部分顺序控制 |
| 消息队列 | 内核队列    | 消息有边界，可按类型接收   | 内核负责消息排队   |
| 共享内存 | 同一块物理内存 | 速度最快，适合大量数据    | 需要信号量、锁等   |
