# 旧版学习计划（归档）

> 本文件保留早期讨论内容。当前正式入口是 [[0.学习规划与目标]]，后续以总规划为准，避免两份计划产生分叉。

---

### 1. 先建立整体认识

先弄明白：浏览器访问一个网址，到底发生了什么？

沿着这条线认识：

域名 → DNS 查询 → 确定目标 IP → 建立连接 → HTTP 请求 → 服务器响应

这一阶段重点分清：

IP：数据送到哪台机器。
端口：送到机器上的哪个服务。
TCP/UDP：应用之间如何传输数据。
HTTP：客户端和服务器如何表达请求、响应。
MAC、交换机、路由器：数据在局域网与不同网络之间如何转发。

先知道它们各自负责什么，不要求一次理解所有细节。

### 2. 学应用层：先 HTTP，再 HTTPS

重点学 HTTP 请求和响应的结构、请求方法、状态码、长连接、Cookie 和 Session。

可以在 Ubuntu 上直接观察：

curl -v http://example.com

HTTPS 放在 HTTP 之后：理解 TLS 如何提供加密、身份验证和完整性保护即可，初期不必深挖密码学算法。

### 3. 重点攻 TCP，这是后端计网的核心

按顺序学：

TCP 与 UDP 的区别。
三次握手、四次挥手。
序列号、确认号、超时重传。
滑动窗口与流量控制。
拥塞控制。
TIME_WAIT、连接关闭与异常断开。

每学一个机制，都问：它解决什么问题？没有它会发生什么？

特别注意：TCP 是字节流，不保留消息边界。所谓“粘包”不能靠一次 recv() 就收到一条完整消息来解决，需要应用协议定义消息长度或分隔符。

### 4. 网络层和链路层补到够用

学习 IP、子网掩码、路由、ARP、ICMP、NAT，配合 ping 理解。

初期不用深挖路由协议和复杂计算题。先能解释：为什么同一局域网和跨网络通信，数据走的路径不同？

### 5. 接上你正在学的 Linux 和 C++

等你对连接、字节流有概念，再用 Linux socket 写：

TCP 回显服务器 → 多客户端服务器 → 简单 HTTP 服务器。

这时把操作系统知识串起来：文件描述符、阻塞与非阻塞、线程、锁，以及后续的 select/poll/epoll。

重点理解 send/recv 的返回值、部分读写、对端关闭和资源释放，而不是只把示例跑起来。

你现在最合适的起点：以《图解网络》的基础篇为主线，每篇记“解决的问题、通信过程、易错点”三项，再做一个小观察实验。 不必等 C++ 和操作系统全部学完才开始计网，但暂时不要直接冲复杂的高并发服务器框架。
