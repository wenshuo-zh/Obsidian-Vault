# HTTP 方法与状态码

## 一、先理解方法解决什么问题

HTTP 方法表示客户端希望服务器对资源做什么。这里的“资源”可以是网页、用户、订单、文件或一条 API 数据，不一定是真实文件。

| 方法 | 入门理解 | 常见特点 |
| --- | --- | --- |
| `GET` | 获取资源 | 参数常放 URL；通常不改变服务端数据 |
| `POST` | 提交数据、创建资源或触发动作 | 数据通常放请求体；可能改变服务端状态 |
| `PUT` | 用完整内容更新或创建指定资源 | 常用于整体替换；通常要求幂等 |
| `PATCH` | 部分更新资源 | 只提交需要修改的字段 |
| `DELETE` | 删除资源 | 目标是删除指定资源 |
| `HEAD` | 只获取响应头，不要响应体 | 可用于检查资源是否存在或大小 |

### GET 示例

```http
GET /users/42?detail=full HTTP/1.1
Host: example.com

```

- `/users/42`：路径；
- `detail=full`：查询参数；
- 本例没有请求体。

### POST 示例

```http
POST /users HTTP/1.1
Host: example.com
Content-Type: application/json
Content-Length: 16

{"name":"alice"}
```

数据放在请求体中，服务器可能创建一个新用户。

## 二、路径、查询参数和请求体

```text
/users/42?detail=full
------  --
路径    查询参数
```

- **路径**：定位资源或交给后端路由匹配；
- **查询参数**：补充筛选、分页、排序等条件；
- **请求体**：提交较完整的数据，常见于 POST、PUT、PATCH。

不要把“路径”理解成服务器磁盘上的文件路径，后端程序通常会根据路径和方法执行业务逻辑。

## 三、幂等性的入门理解

如果同一个请求执行一次或执行多次，最终效果相同，这个请求通常称为**幂等**。

- `GET`：设计上不应改变资源；
- `PUT`：重复提交同样内容，通常结果相同；
- `DELETE`：重复删除同一资源，最终都是“资源不存在”；
- `POST`：可能每次创建新资源，通常不保证幂等。

幂等不等于“请求一定成功”，也不等于“网络只发送一次”。它描述的是重复执行对最终状态的影响。

## 四、状态码：服务器对请求结果的分类

状态行格式：

```http
HTTP/1.1 200 OK
```

状态码是三位数字，第一位表示大类：

| 范围 | 含义 | 说明 |
| --- | --- | --- |
| `1xx` | 信息 | 请求还在处理或提示信息 |
| `2xx` | 成功 | 请求已被正确处理 |
| `3xx` | 重定向 | 需要继续访问其他地址或使用缓存 |
| `4xx` | 客户端请求问题 | 请求格式、权限或资源有问题 |
| `5xx` | 服务端处理问题 | 服务端执行请求时出错 |

## 五、常见状态码

### 2xx 成功

- `200 OK`：请求成功，常见于 GET；
- `201 Created`：资源创建成功，常见于 POST；
- `204 No Content`：成功，但没有响应体。

### 3xx 重定向

- `301 Moved Permanently`：永久重定向；
- `302 Found`：临时重定向；
- `304 Not Modified`：资源未修改，可以使用缓存。

响应中通常会有：

```http
Location: https://example.com/new-path
```

### 4xx 客户端请求问题

- `400 Bad Request`：请求格式或参数不正确；
- `401 Unauthorized`：需要身份认证或认证信息无效；
- `403 Forbidden`：服务器理解请求，但拒绝访问；
- `404 Not Found`：请求的资源不存在或服务器不提供该路径；
- `405 Method Not Allowed`：路径存在，但不支持当前方法。

**`404` 不等于服务器宕机。** 它通常说明服务器已经收到并理解请求，只是找不到对应资源或路由。

### 5xx 服务端问题

- `500 Internal Server Error`：服务端发生未预期错误；
- `502 Bad Gateway`：网关从上游服务收到无效响应；
- `503 Service Unavailable`：服务暂时不可用，可能过载或维护。

## 六、curl 观察实验

### 1. 查看 GET 请求

```bash
curl --http1.1 -v --max-time 15 https://example.com/
```

重点看：

- `> GET / HTTP/1.1`：请求方法和路径；
- `< HTTP/1.1 ...`：响应状态行；
- `Location`：是否发生重定向。

### 2. 查看响应头

```bash
curl --http1.1 -i https://example.com/
```

### 3. 观察 POST 请求

```bash
curl --http1.1 -v \
  -H 'Content-Type: application/json' \
  -d '{"name":"alice"}' \
  https://httpbin.org/post
```

`-d` 会发送请求体，并且 curl 默认使用 POST。若环境无法访问 `httpbin.org`，先记录连接失败，不要把失败误认为 HTTP 状态码。

### 4. 观察重定向

```bash
curl --http1.1 -i http://httpbin.org/redirect/1
curl --http1.1 -i -L http://httpbin.org/redirect/1
```

- 不加 `-L`：只看第一次响应，通常能看到 `3xx` 和 `Location`；
- 加 `-L`：curl 自动跟随重定向，继续访问目标地址。

本次实验使用 `http://httpbin.org/redirect/1`，实际输出如下。

#### 不跟随重定向：只得到 302

```bash
curl --http1.1 -i --max-time 15 http://httpbin.org/redirect/1
```

![[Pasted image 20261004054610.png]]

响应状态为 `HTTP/1.1 302 FOUND`，并带有 `Location: /get`。这表示服务器要求客户端临时访问 `/get`，本次 curl 不会自动发起第二次请求。

#### 跟随重定向：302 -> 200

```bash
curl --http1.1 -i -L --max-time 15 http://httpbin.org/redirect/1
```

![[Pasted image 20261004054452.png]]

输出先出现 `HTTP/1.1 302 FOUND`，curl 读取 `Location: /get` 后再次请求目标地址，最终得到 `HTTP/1.1 200 OK` 和 JSON 响应。因此，`-L` 不是把 `302` 改成 `200`，而是让客户端继续完成一次新的 HTTP 请求。

这也说明：判断一次访问是否成功，不能只看第一行状态码；需要确认是否发生重定向，以及客户端是否跟随并取得最终响应。

## 七、易错点

1. 方法是客户端的意图，不是服务器一定完成的结果；最终要结合状态码判断。
2. `401` 和 `403` 不一样：前者侧重“需要认证/认证失败”，后者侧重“已理解但拒绝访问”。
3. `404` 表示资源或路由未找到，不等于 TCP 连接失败，也不等于服务器宕机。
4. `3xx` 不一定是错误，要结合 `Location` 和客户端是否跟随重定向判断。
5. HTTP 状态码只表示 HTTP 层结果；底层 DNS 失败或 TCP 连接失败时，可能根本没有 HTTP 状态码。
