# HTTP/1.1 长连接与分块传输

## 一、本次重点

- 理解为什么要复用 TCP 连接；
- 区分 HTTP 长连接和 TCP 长连接；
- 区分 `Content-Length` 与 `Transfer-Encoding: chunked`；
- 理解 HTTP 如何判断一条响应正文在哪里结束。

完成标准：能解释 `keep-alive` 和 `chunked` 分别解决什么问题，并能从 curl 输出中找到对应响应头。

## 二、为什么需要长连接

如果每发送一个 HTTP 请求都重新建立一次 TCP 连接，会重复产生三次握手、慢启动和资源分配开销。

长连接的核心是：

```text
同一条 TCP 连接
    ├── HTTP 请求 1 / 响应 1
    ├── HTTP 请求 2 / 响应 2
    └── HTTP 请求 3 / 响应 3
```

HTTP/1.1 默认倾向于复用连接。任意一方都可以根据超时、错误或请求头决定关闭连接。

```http
Connection: close
```

表示本次通信完成后关闭连接。

## 三、长连接不等于永久连接

`keep-alive` 只是暂时不关闭 TCP 连接，不代表连接永远存在。服务器通常会设置空闲超时和最大请求数量。

同时需要区分：

- HTTP 决定是否继续复用连接；
- TCP 负责可靠传输字节流；
- socket 是操作系统提供给程序操作连接的接口。

## 四、如何判断响应正文结束

同一条 TCP 连接上可能连续传输多个 HTTP 报文，因此客户端必须知道当前正文在哪里结束。

常见方式有：

1. `Content-Length`：提前给出正文总字节数；
2. `Transfer-Encoding: chunked`：把正文拆成多个块；
3. 关闭连接：连接关闭时正文结束，通常不利于连接复用；
4. 某些响应本身没有正文，例如 HEAD、204、304。

## 五、Content-Length

```http
Content-Length: 125
```

表示后面正文正好有 125 字节。接收方读取满 125 字节，就知道当前正文结束。

优点是简单；限制是发送前必须知道完整正文长度。

## 六、分块传输

当服务端一边生成数据、一边发送数据，可能无法提前知道总长度。这时可以使用：

```http
Transfer-Encoding: chunked
```

简化后的正文格式：

```http
5\r\n
Hello\r\n
6\r\n
 World\r\n
0\r\n
\r\n
```

每个块由以下部分组成：

```text
十六进制块长度 + CRLF
数据 + CRLF
```

长度为 `0` 的块表示正文结束。

`chunked` 是 HTTP/1.1 的报文分帧方式，不等于 TCP 分包。TCP 仍然只是字节流，实际一次 `recv` 可能只收到半个块，也可能同时收到多个块。

## 七、管道传输与队头阻塞（手写补充）

HTTP/1.1 的管道传输（pipelining）允许客户端在同一条 TCP 连接上连续发送多个请求，而不必等待前一个响应返回。

但响应通常必须按照请求顺序返回：

```text
请求 1 ───────> 响应 1（较慢）
请求 2 ───────> 响应 2（即使先准备好，也要等待响应 1）
```

因此前面的慢响应会阻塞后面的响应，这叫**队头阻塞（Head-of-Line Blocking）**。这是 HTTP/1.1 管道传输的局限；这里先理解现象，不展开 HTTP/2。

## 八、curl 实验

### 1. 观察响应头

```bash
curl --http1.1 -v --max-time 15 http://example.com/
```

重点观察：

```text
Connection: keep-alive
Content-Length: ...
Transfer-Encoding: chunked
```

服务端可能选择其中不同组合，实际结果以输出为准。

### 2. 强制请求关闭连接

```bash
curl --http1.1 -v --max-time 15 \
  -H 'Connection: close' \
  http://example.com/
```

观察响应结束后连接是否关闭，并与普通请求对比。

### 3. 查看 curl 连接复用提示

```bash
curl --http1.1 -v --max-time 15 \
  http://example.com/ \
  http://example.com/
```

如果服务器和网络条件允许，第二个请求可能复用第一条连接。重点查看 `Re-using existing connection` 等提示。

## 九、易错点

1. 长连接表示复用 TCP 连接，不表示 HTTP 请求没有边界。
2. `Content-Length` 的单位是字节，不是字符。
3. `chunked` 的块长度使用十六进制。
4. TCP 拆包与 HTTP 分块是不同层次的问题。
5. 响应头出现 `keep-alive` 不保证连接一定会长时间保留，超时后仍会关闭。
