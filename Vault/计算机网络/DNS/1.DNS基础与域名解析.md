# DNS 基础与域名解析

## 一、本次学习目标

- 说清 DNS 解决什么问题，以及域名和 IP 的关系；
- 区分域名、IP、端口三者职责；
- 看懂一次 `域名 -> IP -> TCP 连接 -> HTTP 请求` 的过程；
- 会用 `nslookup` 或 `dig` 查看解析结果；
- 理解 C++ 后端中 `getaddrinfo` 的作用。

本次只学习 DNS 基础，不深入递归服务器实现、DNSSEC 和复杂缓存策略。

## 二、DNS 解决什么问题

人容易记住 `example.com`，网络通信需要连接类似 `93.184.216.34` 的 IP 地址。DNS（Domain Name System）负责把域名解析为 IP 地址。

```text
域名：example.com       找名字
IP：93.184.216.34       找机器
端口：80 或 443         找机器上的服务
```

DNS 只负责“名字到地址”的查询，不负责建立 TCP 连接，也不负责传输 HTTP 内容。

## 三、一次访问的顺序

```text
1. 应用拿到域名 example.com
2. 查询 DNS，得到一个或多个 IP
3. 根据端口建立 TCP 连接
4. 如果是 HTTPS，先完成 TLS 握手
5. 发送 HTTP 请求并接收响应
```

域名可能对应多个 IP，DNS 返回的结果也可能随时间、地域和负载变化。客户端通常会尝试其中一个地址，失败时再尝试其他地址。

## 四、常见记录类型

| 类型 | 作用 |
| --- | --- |
| `A` | 域名映射到 IPv4 地址 |
| `AAAA` | 域名映射到 IPv6 地址 |
| `CNAME` | 域名指向另一个域名 |
| `MX` | 指定邮件服务器 |

入门阶段重点看 `A` 和 `AAAA`。

## 五、Linux 实验

### 1. 查询域名

```bash
nslookup example.com
```

如果安装了 `dig`，也可以执行：

```bash
dig example.com A
dig example.com AAAA
```

重点观察：查询的域名、DNS Server、回答中的 IP 和 TTL。TTL 表示结果可以被缓存多长时间，不是 TCP 连接寿命。

### 2. 对比域名访问和 IP 访问

```bash
curl --http1.1 -v --max-time 15 http://example.com/
```

重点观察 `Trying ...` 和 `Connected ...`：前者通常显示解析后的 IP，后者表示已经连接到目标端口。HTTP/1.1 的 `Host: example.com` 仍然保留，因为服务器可能依靠 Host 区分多个网站。

### 3. 查看本机解析配置

```bash
cat /etc/resolv.conf
getent hosts example.com
```

`/etc/resolv.conf` 常记录本机使用的 DNS 服务器；`getent hosts` 会使用系统解析配置查询主机名。

## 六、C++ 后端连接：getaddrinfo

`getaddrinfo` 把“主机名 + 服务名/端口”转换为可供 `connect` 使用的地址结构。它可以同时处理 IPv4、IPv6，不应手动假设只有 `sockaddr_in`。

```cpp
#include <netdb.h>
#include <sys/socket.h>
#include <iostream>

int main() {
    addrinfo hints{};
    hints.ai_socktype = SOCK_STREAM;

    addrinfo* result = nullptr;
    int rc = getaddrinfo("example.com", "80", &hints, &result);
    if (rc != 0) {
        std::cerr << "getaddrinfo: " << gai_strerror(rc) << '\n';
        return 1;
    }

    for (addrinfo* p = result; p != nullptr; p = p->ai_next) {
        std::cout << "family=" << p->ai_family
                  << ", socktype=" << p->ai_socktype << '\n';
    }
    freeaddrinfo(result);
}
```

编译：

```bash
g++ dns_lookup.cpp -o dns_lookup -Wall
```

关键点：检查返回值、遍历链表、使用 `gai_strerror` 获取错误信息，最后调用 `freeaddrinfo` 释放结果。

## 七、易错点

1. DNS 成功不代表 TCP 连接一定成功，解析、连接、HTTP 响应是不同阶段。
2. IP 找到的是机器，端口找到的是机器上的服务。
3. `curl` 没有拿到 HTTP 状态码时，可能卡在 DNS 或 TCP 阶段。
4. DNS 返回多个地址是正常现象，不能假设域名永远只有一个 IP。
5. TTL 是 DNS 缓存时间，不是 HTTP 或 TCP 的超时时间。
