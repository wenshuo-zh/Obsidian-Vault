## 学计网是为了什么

我的目标是 **C++ 后端求职**。计网不是孤立的一门课，要逐步和 C++、Linux、操作系统知识接起来。

- 能解释客户端和服务器如何通信。
- 能用 Linux socket 写简单网络程序，理解连接和数据读写。
- 面试时能讲清机制解决的问题，而不只是背名词。

## 笔记不是学习的终点

**先理解，再观察验证，最后整理笔记。** 不要等笔记排版完善，才继续学习。

- 框架已经搭好，后面优先补自己的理解，不重复抄整篇资料。
- 笔记重点记录：这个机制解决什么问题、通信过程、易错点。
- 记录疑问和纠正误解，比美化排版更重要。
- 暂时不懂的地方先记下来，避免一个细节卡住整个学习进度。

判断是否学会：合上资料，能否用自己的话解释，并指出实验中对应的现象？

## 每学一个机制，先问为什么

**它解决什么问题？没有它会发生什么？**

例如，学 HTTP 请求头时，不只记住 `Host` 的名称，还要追问：同一个 IP 对应多个网站时，服务器怎样知道客户端要访问哪个网站？

当前先学 HTTP，再学 HTTPS；后续重点理解 TCP，最后接上 socket 编程。不必等其他科目全部学完才开始计网，也不急着直接做复杂的高并发服务器。

## HTTP 的第一个观察实验

在 Ubuntu 或 VSCode Remote-SSH 的终端执行：

```bash
curl --http1.1 -v http://example.com/
curl --http1.1 -i http://example.com/
```

缺少 curl 时安装：

```bash
sudo apt update
sudo apt install -y curl
```

观察目标：

- `-v` 输出中的 `*` 表示连接相关信息，`>` 表示发出的请求，`<` 表示收到的响应。
- 找到请求方法、路径、`Host` 和响应状态码。
- 观察 `Content-Type` 如何描述响应正文的类型。
- 在 `-i` 输出中找到响应头与正文之间的空行。
- 实际状态码可能不是 `200`；若遇到重定向或错误，先记录现象，不照抄预期结果。

这个实验用于观察 **HTTP/1.1 文本报文**；不是所有 HTTP 版本都用这种文本格式。

实验后只补三项：实际观察到什么、它印证了哪个知识点、还有什么疑问。不需要立刻写 C++ 程序。

### 当前实验记录

- 已在当前环境执行 curl：DNS 解析成功，但外部 TCP 连接被运行环境拦截，未拿到 HTTP 响应报文。
