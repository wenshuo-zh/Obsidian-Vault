# tcpdump 与 Wireshark 抓包基础

## 一、学习目标

- 理解 tcpdump 与 Wireshark 的分工；
- 看懂网卡、接口、pcap、捕获过滤器和显示过滤器；
- 逐项理解常用命令参数；
- 在 Ubuntu 虚拟机捕获，在 Windows Wireshark 分析。

默认流程是：**Ubuntu 用 tcpdump 捕获原始报文，Windows 用 Wireshark 图形化解析**。VMware 的 NAT、桥接或仅主机模式可能让 Windows 宿主机看不到完整的虚拟机报文，因此不使用 Windows 网卡替代 Ubuntu 内抓包。

## 二、先认识网卡和接口

```bash
ip addr
```

查看 IP 地址。`lo` 是回环接口，`127.0.0.1` 的本机通信经过它；`ens33`、`eth0` 等通常是虚拟机以太网接口；`inet` 后面是 IPv4 地址。

```bash
ip link
```

查看接口名称、启用状态和链路状态。`ip addr` 偏重地址，`ip link` 偏重接口本身。

```bash
sudo tcpdump -D
```

列出 tcpdump 可以监听的接口。实际使用优先写接口名，例如 `-i lo`；不知道流量经过哪张网卡时可以使用 `-i any`。

## 三、tcpdump 参数

### 1. 实时抓包

```bash
sudo tcpdump -i any -nn
```

- `sudo`：打开抓包接口通常需要权限；
- `-i any`：监听所有接口；
- `-nn`：不解析域名和端口服务名，保留数字；
- 没有过滤器：所有接口上的报文都可能显示。

命令等待报文时看起来像卡住是正常的，按 `Ctrl+C` 停止。

### 2. 限制数量和协议

```bash
sudo tcpdump -i any -nn -c 10
sudo tcpdump -i any -nn 'tcp'
sudo tcpdump -i any -nn 'tcp port 443'
```

- `-c 10`：捕获 10 个报文后自动退出；
- `'tcp'`：只捕获 TCP；
- `'tcp port 443'`：源端口或目的端口为 443 的 TCP 报文。端口 443 不等于一定能看到明文 HTTPS。

### 3. 保存和读取 pcap

```bash
sudo tcpdump -i any -nn -s 0 -w tcp-test.pcap 'tcp port 443'
tcpdump -nn -r tcp-test.pcap
```

- `-s 0`：保存完整报文，避免负载被截断；
- `-w tcp-test.pcap`：写入 pcap 文件，不在终端逐包打印；
- `-r`：从 pcap 读取，不再监听网卡。

读取时也可以继续过滤：

```bash
tcpdump -nn -r tcp-test.pcap 'tcp[tcpflags] & tcp-fin != 0'
```

该表达式只显示带 FIN 标志的 TCP 报文。

### 4. 输出细节

```bash
sudo tcpdump -i lo -nn -tttt -v 'tcp port 8000'
```

- `-i lo`：只监听回环接口；
- `-tttt`：显示完整、易读的时间；
- `-v`、`-vv`、`-vvv`：逐级增加输出细节；
- `-A`：尝试以 ASCII 显示明文负载；
- `-X`：同时显示十六进制和 ASCII。

## 四、tcpdump 捕获过滤器

捕获过滤器决定**哪些报文会被保存**。常用写法：

| 表达式 | 含义 |
| --- | --- |
| `tcp`、`udp`、`icmp` | 协议类型 |
| `host 192.168.1.10` | 源或目的主机 |
| `src host 192.168.1.10` | 源主机 |
| `dst host 192.168.1.10` | 目的主机 |
| `port 8000` | 源或目的端口 |
| `src port 8000` | 源端口 |
| `dst port 8000` | 目的端口 |

组合条件：

```bash
sudo tcpdump -i any -nn 'tcp and host 192.168.52.129 and port 443'
sudo tcpdump -i any -nn 'tcp port 80 or tcp port 443'
sudo tcpdump -i any -nn 'tcp and not port 22'
sudo tcpdump -i any -nn 'tcp and (port 80 or port 443)'
```

`and` 表示同时满足，`or` 表示满足任意条件，`not` 表示排除。建议把整个表达式放在单引号中。

## 五、tcpdump 一行输出怎么看

```text
IP 127.0.0.1.54321 > 127.0.0.1.8000: Flags [S], seq 100, win 65495, length 0
```

- `127.0.0.1.54321`：源 IP 和源端口；
- `>`：方向；
- `127.0.0.1.8000`：目的 IP 和目的端口；
- `[S]`：SYN；
- `seq 100`：起始序列号；
- `win`：通告窗口；
- `length 0`：TCP 负载长度。

常见标志：`[S]` 是 SYN，`[S.]` 是 SYN+ACK，`[.]` 是纯 ACK，`[P.]` 常表示携带数据，`[F.]` 是 FIN+ACK，`[R.]` 是 RST+ACK。

## 六、可重复的本地实验

终端一启动 HTTP 服务：

```bash
python3 -m http.server 8000 --bind 127.0.0.1
```

终端二开始抓包：

```bash
sudo tcpdump -i lo -nn -s 0 -c 30 -w tcpdump-http-local.pcap 'tcp port 8000'
```

含义是：在回环接口捕获完整 TCP 报文，只保留 8000 端口，最多保存 30 个，写入 pcap。

终端三产生请求：

```bash
curl --http1.1 -v --max-time 5 http://127.0.0.1:8000/
```

读取捕获结果：

```bash
tcpdump -nn -r tcpdump-http-local.pcap
```

重点寻找类似顺序：`[S]`、`[S.]`、`[.]`、HTTP 数据、`[F.]` 或 `[R.]`。实际数量受 curl、HTTP 长连接和内核行为影响，不要求完全一致。

## 七、Wireshark 分析

将 pcap 从 Ubuntu 传到 Windows：

```powershell
scp ubuntu用户名@虚拟机IP:~/tcpdump-http-local.pcap .
```

在 Wireshark 中打开文件，认识三个区域：上方是报文列表，中间是协议分层详情，下方是原始字节。点击 TCP 报文并展开 `Transmission Control Protocol`，观察 `Sequence Number`、`Acknowledgment Number`、`Flags` 和 `Len`。右键报文选择 **Follow -> TCP Stream** 可以按连接查看完整通信。

常用 Wireshark **显示过滤器**：

```text
tcp.port == 8000
tcp.stream eq 0
tcp.flags.syn == 1 && tcp.flags.ack == 0
tcp.flags.fin == 1
tcp.analysis.retransmission
ip.addr == 127.0.0.1
```

`tcpdump` 的 `tcp port 8000` 和 Wireshark 的 `tcp.port == 8000` 不是同一套语法：前者是捕获过滤器，决定报文是否保存；后者是显示过滤器，只改变已经打开的 pcap 中哪些报文显示。捕获时漏掉的报文，Wireshark 之后无法恢复。

## 八、常见排查

1. 权限错误：在抓包命令前加 `sudo`。
2. 抓不到包：先执行 `sudo tcpdump -D`，本机通信优先用 `-i lo`，并先去掉复杂过滤器。
3. pcap 为空：确认先启动 tcpdump，再执行 curl；`-w` 模式不逐包打印是正常的。
4. HTTPS 看不到 HTTP 正文：TLS 加密了应用数据；本地实验先使用明文 HTTP。
5. 连接问题：结合 `ss -lntp` 判断端口是否监听，再用 tcpdump 看 SYN、SYN+ACK、RST、FIN。
