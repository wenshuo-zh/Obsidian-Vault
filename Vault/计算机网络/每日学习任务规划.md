## 今日学习记录

- 已手绘 HTTP 请求和响应的四部分，结构划分正确。
- 请求：请求行、请求头、空行、可选请求体。
- 响应：状态行、响应头、空行、可选响应体。
- 细节订正：`Accept` 表示客户端希望接收的响应媒体类型；`Content-Type` 表示当前请求体或响应体的媒体类型；`Content-Length` 必须和实际正文的字节数一致，示例值不能随便填写。
- curl 实验的目的不是下载网页，而是观察 DNS、TCP 和 HTTP 请求/响应之间的实际顺序；具体命令解释见 [[1.HTTP请求访问流程]]。
- curl 实验成功：连接到 `example.com:80`，发送 `GET / HTTP/1.1`，收到 `HTTP/1.1 200 OK`。
- 请求中观察到 `Host: example.com`、`User-Agent: curl/7.81.0`、`Accept: */*`；响应中观察到 `Content-Type: text/html; charset=utf-8`、`Transfer-Encoding: chunked` 和 `Connection: keep-alive`。
- 最后一个概念任务已完成：TCP 负责连接管理和可靠字节流传输，HTTP 负责应用层请求/响应报文的格式与语义；两者解决的问题不同。
